# 保持期限と保管庫

更新が止まったページを配信から外し、一覧の末尾の「保管庫」へタイトルだけ残します。使い終わったページが配信先に残り続けると、URLを知る人がいつまでも開ける状態になるためです。元のHTMLは手元のリポジトリに残っているので、要るときはいつでも配信へ戻せます。

設定ファイルの `content.retainDays` に日数を書くと有効になります。書かなければ、これまでどおり全ページを配信し続けます。

```yaml
content:
  retainDays: 30               # 最終更新から30日を過ぎたページを保管庫へ移す
  pages:
    - path: reports/q3-plan.html
      keep: 2026-03-31         # 見直し日。この日までは古くても配信を続ける
```

## どのページが保管庫へ移るか

`publish`（と `build`）のたびに、ページごとに次の順で判定します。どれにも当てはまらないページが保管庫へ移ります。

| 配信を続ける理由 | 判定に使うもの |
|---|---|
| 最終更新から `retainDays` 日以内 | 元のHTMLファイルの更新日時 |
| 見直し日がまだ来ていない | そのページの `keep`（当日まで有効） |
| 進行中フィルターに載っているテーマ | `content.shelf` の項目（`done` と期限切れを除く） |

最終更新は元のHTMLファイルの更新日時です。ページを書き直せば、それだけで配信へ戻ります。`git clone` や `git checkout` をし直すと更新日時がその時刻に揃うため、次の `publish` では全ページが新しい扱いになります。

画面のスターや「最近開いた」は判定に使いません。これらは本人の画面からクラウドへ保存される値で、`publish` を動かす手元のCLIからは読めないためです。長く残したいページには `keep` を書くか、テーマを進行中フィルターへ入れてください。

## 保管庫へ移ったページ

- 配信先（S3）から消えるので、そのページに発行済みの共有URLも開けなくなります。共有を個別に止めたいときにも使えます
- 一覧の末尾の「保管庫 ◯件」から、タイトルと最終更新を確認できます。行は開けません
- `html-share share` で保管庫のページを指定すると、戻し方を案内して止まります
- 一度に多くのページが保管庫へ移っても、`publish` のバケット縮小チェック（2割以上減る送信を止める検査）では意図した削除として数えます

## 配信へ戻す

```bash
html-share page revive <slug>
```

設定ファイルのそのページに `keep`（今日から14日後）を書き、続けて `publish` します。日数は `--days` で変えられ、`--no-publish` を付けると設定の書き換えだけで止まります。設定ファイルのコメントと並び順はそのまま残ります。見直し日を過ぎても更新が無ければ、また保管庫へ戻ります。

画面の保管庫で行の「戻す」を押すと、このコマンドを書いた依頼がインボックスへ置かれます。手元で `/inbox` を実行すると、エージェントが引き取って戻します。
