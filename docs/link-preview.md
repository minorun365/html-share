# リンクプレビュー（OGP）

共有URLをSlack・Teams・Xへ貼ると、ただのURLではなくカードで表示されます。

| 出るもの | 中身 |
|---|---|
| アプリ名 | `content.siteName`（省略時は `#HTML共有くん`） |
| ページ名 | 設定の `title`、無ければHTMLの `<title>` |
| 説明文 | ヒーローのリード文（`<p class="sub">`）→ `lead` → 最初の段落の順に使う |
| 画像 | 同梱のカード画像（`assets/og-card.jpg`）。`content.ogImageUrl` で差し替え、`false` で出さない |
| カードの大きさ | `content.ogCardType`（省略時は各媒体でいちばん小さいカードの `summary`） |

画像は次の3通りです。

- 既定では同梱の画像を使います。publish が配信先の `/og/card.jpg` へ配置し、全ページのカードで参照します。配信面は署名付きURLでしか開けませんが、`/og/*` だけは署名なしで開ける設定にしているため、クローラーも画像を取得できます。ここに置くのはこの1枚だけで、ページの中身は `/og/` に置きません。
- 自前の画像を使う場合は、`content.ogImageUrl` に https の絶対URL を書きます。`siteName` を変えたときは、画像の中のアプリ名と揃うようにこちらで差し替えてください。
- 画像を出さない場合は、`content.ogImageUrl: false` を設定します。この場合 `og:image` は出力されず、SlackとXはテキストだけのカードになり、Teamsは `og:image` が無いとカードを出しません。

既存の環境で同梱の画像を使い始めるには、`/og/*` の配信ルールを足す `deploy` と `publish` の両方が必要です。

ページ自体が `og:title` を持っている場合は、そのページには何も足しません。

## 画像を置くときの注意

`og:image` はページ本体とは別のリクエストで取得されるため、タグが正しくても画像だけ取得に失敗します。しかも失敗したことは表に出ず、Xは大きいカードではなく小さいカードで表示するので、「なぜかOGPが出ない」と見えても原因はHTML側にありません。

- 画像URLに直接アクセスし、`200` かつ `Content-Type: image/*` が返ることを確かめてください。S3 + CloudFront OAC は「オブジェクトが無い」状態を **404 ではなく 403** で返すので、権限の問題だと読み違えやすいです。
- `Cache-Control: immutable` は付けないでください。「中身は永久に変わらない」という宣言になり、画像を差し替えてもクローラーが取り直しません。`public, max-age=3600` 程度が無難です。
- 画像を差し替えたら、URLの末尾に `?v=20260920` のようなクエリを足してください。SNSは画像をURLの文字列で覚えるので、ファイル名が同じままだと古い画像が出続けます。ファイル名のほうを変えると、既存の投稿が参照している画像が消えます。
- 正方形の画像は、要素を中央の横帯に収めて作ってください。同じ画像でも、パソコン版のSlackは小さな正方形のサムネイル、スマホ版のSlackは横長に切り抜いた大きな画像として表示されます。クローラーは1回しか取りに来ないため、表示先ごとに画像を出し分けることはできません。上下いっぱいに文字を並べると、スマホ版で上下が詰まって見えます。アプリ名は1行にし、上下に余白を残すとどちらの表示でも収まります。
- `robots.txt` でクローラーを止めないでください。検索インデックスからの除外は `X-Robots-Tag` と `<meta name="robots">` で行っています。`Disallow: /` を置くと、Slack / Teams / X のクローラーまで止まってしまいます。
- SVGは使えません。JPEG か PNG を置いてください。

## カードの大きさ

既定は各媒体でいちばん小さいカードになる `summary` です。画像を指定しても大きくなりません。

```yaml
content:
  ogCardType: summary_large_image   # 横長の大きなカードにしたいときだけ
```

`summary_large_image` は 1200×630 前後の横長画像を前提にした表示です。正方形やロゴを渡すと引き伸ばされます。ページごとに別々の画像を用意しない運用では、小さいカードのほうが収まりよく見えます。

> メタタグは `<meta charset>` の後ろへ入れています。日本語のページ名が文字コード宣言より前に出ると、クローラー側で文字化けすることがあるためです。
